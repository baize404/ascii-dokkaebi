# 遊戲設計與美術風格規範

## 1. 定位與核心循環

韓國民間傳說 × ASCII 藝術 × 3D 探索 × 環境解謎 × 暗黑童話。目標遊玩時間 15–25 分鐘。

核心循環：**探索世界 → 發現線索 → 推理解謎 → 獲得回饋 → 世界產生變化 → 解鎖新區域**。

| 循環 | 具體例子 |
| --- | --- |
| 探索 → 線索 | 走進廚房看到字條；在倉庫門口發現發光腳印 |
| 線索 → 推理 | 「照著一年的順序」＋屏風「梅—早春……」＋石燈刻紋 → 點燈順序 |
| 回饋 | 點對時：四季粒子（梅瓣、螢光、楓葉、雪）、上升的五聲音階、燈光 |
| 世界變化 | 四盞燈亮 → 금줄斷開 → 山丘開放；結局時月光照亮全村、窗戶逐一亮起 |

## 2. 五章流程

| 章 | 玩家做什麼 | 解鎖條件 |
| --- | --- | --- |
| 一　消失的月亮 | 開場過場（可跳過）；用實際移動與互動完成教學；調查장승 | 讀完장승 |
| 二　沉睡的村落 | 廚房字條與葫蘆瓶 → 장독대選最大的甕 → 轉三次轆轤拿鑰匙 → 用葫蘆瓶裝막걸리；可選：腳印、부적、할머니、池塘、黑貓 | 兩樣供品都到手 |
| 三　四季的石燈 | 從屏風、장승的話和刻紋推理順序並點燈 | 四盞燈全亮，금줄斷開 |
| 四　鬼怪的遊戲 | 獻上供品，도깨비登場；三題觀察題；甕遊戲；可選：歸還감투 | 找到藏月亮的甕 |
| 五　月亮回歸 | 電影式過場、結算（時間、探索度、提示、失誤、圖鑑、成就） | — |

章節由 `GameState.chapter` 依進度推算；玩家可以先點燈再找供品，不會卡關。

## 3. 謎題與可解性

| 謎題 | 線索來源 | 答錯回饋 | 提示（三段） | 可解性保證 |
| --- | --- | --- | --- | --- |
| 장독대選甕 | 廚房字條「最大的甕」 | 聞到醬油／辣椒醬，可再選 | 字條 → 位置 | 沒看字條也能逐一嘗試 |
| 轆轤 | 實際操作三次 | 可中途離開，進度保留 | — | 單元測試 |
| 倉庫的酒 | 「需要容器」→ 廚房葫蘆瓶 | 記下線索，回來再裝 | 第三段點出葫蘆瓶 | 單元測試覆蓋兩種順序 |
| 石燈 | 장승、屏風、刻紋三處 | 只有那一盞熄滅；連錯兩次提示去看「提示」 | 一年從哪開始 → 屏風 → 梅是第一盞 | 刻紋隨機但屏風固定；單元測試 |
| 觀察題 | 只抽玩家已發現的線索（장승、금줄、老樹為必經，保證至少三題） | 도깨비大笑，可選看提示 | 去日誌找線索 → 題目專屬提示 → 劃掉一個錯誤選項 | 30 個隨機種子的單元測試 |
| 甕遊戲 | 觀察 | 重來一輪，失誤兩次後自動放慢 | 盯著甕 → 放慢 → 最後透光 | 邏輯與動畫共用同一組交換序列 |
| 真結局（隱藏） | 黑貓叼著帽子、할머니「東西破了自己補」 | 破帽子也能還，但只有一般結局 | — | 單元測試 |

`tests/unit/Systems.test.js` 的「關卡可解性」用與遊戲相同的碰撞資料建立尋路網格，檢查每個互動點都站得上去、從起點走得到，以及금줄斷開前後祭壇的可達性。

## 5. 美術風格規範

**關鍵詞**：Atmospheric、Cinematic、Mysterious、Korean Folklore、ASCII Art、Dark Fairy Tale、Stylized 3D、Diegetic Lighting。

### 色票

| 名稱 | 色碼 | 用途 |
| --- | --- | --- |
| 深夜黑 | `#080D16` | 背景、霧、介面底色 |
| 霧靛藍 | `#263C50` | 屋頂、遠景色調、薄霧 |
| 燈籠金 | `#F2BD68` | 燈火、可互動提示、介面線框與重點文字 |
| 鬼火青 | `#67C5DC` | 超自然（鬼火、腳印、도깨비）、詞彙註解 |
| 丹青紅 | `#D65F4C` | 介面轉角、錯誤回饋、地圖任務標記、辣椒 |
| 月光白 | `#E2E8EF` | 內文、月光 |

### 光線與導引（Diegetic Lighting）

- 可互動的地方用場景本身的光吸引注意：廚房亮窗、石燈、鬼火、發光腳印。
- 靠近可互動物件時，地上出現燈籠金光圈；不使用指向答案的箭頭（只有開場教學用一個光點指向장승）。
- 夜間神秘但要看得清：每個角色都有自己的光源（燈籠、鬼火）；道路用石板與踏腳石提高亮度。

### 層次與 ASCII

- 前景：角色與互動物件有深度輪廓線（`| \ - /`）與較高飽和度。
- 中景：建築用屋瓦紋路、窗櫺讓字元有規律的紋理。
- 背景：遠處依距離融入霧靛藍、亮度降低；天空只有星點。
- 字元密度三段可選；亮度映射用 gamma 曲線讓暗部仍有 `.` `:` 的細節。

### 介面

- 墨色半透明底、1px 燈籠金細線框、左上角丹青紅小方塊；標題與章節用明體（serif）。
- HUD 預設只顯示一行目前目標；所有資訊都收在可展開的面板。
- 禁止：霓虹光、科技感面板、與韓國民俗無關的圖示。
- 觸控按鈕至少 44×44 CSS 像素；支援瀏海與安全區域；直式、橫式皆可。

## 6. 文化內容原則

- 民俗圖鑑每一條都分成「真實文化」與「遊戲設定」，並附上來源連結。
- 不確定的說法（例如도깨비愛喝막걸리）在圖鑑中明確標示為劇情設定，不當作考據。
- 有爭議或多種說法的內容（例如四君子與季節的對應）不拿來考常識：遊戲中以屏風上的題字為準。
- 석등原本是佛寺裡的石燈，村落參道上排四盞是虛構設計，圖鑑中說明。

# 3.0 補充規範：The Living Village

## 7. ASCII 渲染規範

| 項目 | 規範 |
| --- | --- |
| 四件事分開控制 | 字元密度（每格 CSS 像素）、場景取樣（每格幾×幾個場景像素）、Canvas DPR、陰影解析度各自設定。提高 DPR 只讓筆畫更銳利，**不改變格數** |
| 字元密度 | Classic 9 px（手機 8）、Fine 6 px（5）、Ultra 4 px、Cinematic 3 px；自適應會依實際幀率在這些等級之間切換 |
| 場景取樣 | 2×2／4×4／8×8；場景離屏貼圖 = 格數 × 取樣倍率，超過畫質上限時自動降一級，避免爆記憶體 |
| 處理流程 | 場景（含深度與物件遮罩）→ 縮減 pass：面積平均、細小物件覆蓋率、格內深度不連續 → 分類 pass：剪影 Sobel、深度二階差分找法線轉折、ACES 色調映射＋sRGB、與上一幀的遲滯 → 合成 pass：字元圖集取樣 |
| 物件遮罩 | 角色與互動物件標記為「重要」：優先保留輪廓與細小肢體（手指、門環、火焰尖端）；水面標記為柔和表面，不畫硬邊 |
| 字元圖集 | 依每個字元實際的筆畫覆蓋率挑選等距亮度階梯；每個字元獨立格子＋留白邊＋mipmap，避免相鄰字元滲色。預設 **Pure ASCII 只用可列印 ASCII 字元** |
| 抗閃爍與抗抖動 | **只在鏡頭靜止時**才把鏡頭平移慢慢對齊字元格、啟用字元遲滯（靜止畫面不閃字）；鏡頭移動時兩者都關閉，畫面完全平順地捲動（移動中對齊格線會讓角色與背景一格一格地跳） |
| 四種模式 | Pure ASCII（完整純字元）／HD ASCII（多層次輪廓、預設）／Hybrid（字元＋經深度遮擋的連續光暈，燈火與薄霧較柔和）／原始 3D。切換只改畫面，不重設位置、任務、動畫或存檔 |

## 8. 角色與動畫規範

**骨架**：所有人形角色共用同一套程序化骨架產生器（`src/world/rig/humanoid.js`），以 three 的 `Bone`、`Skeleton`、`SkinnedMesh` 建立：

```
Root → Pelvis → Spine → Chest → Neck → Head
Chest → Clavicle → Shoulder（上臂）→ Elbow（前臂）→ Wrist → Hand → Finger、Thumb
Pelvis → Hip（大腿）→ Knee（小腿）→ Ankle → Foot → Toe
次級骨：裙擺 Skirt.F/B/L/R、衣帶 Goreum、辮子 Braid1–3 與 댕기（紅緞帶）、Belly
```

| 角色 | 三角面 | 骨頭 | 重點 |
| --- | --- | --- | --- |
| 主角（提燈的孩子） | 約 11,800 | 40 | 韓服領口與袖口層次、上紅下白、辮子與紅色 댕기、手指與腳趾、右手提著上藍下紅的청사초롱 |
| 할머니 | 約 11,200 | 36 | 髮髻、灰藍裙、打盹、揉眼睛、起身、揮手 |
| 도깨비 | 約 9,900 | 35 | 藍皮膚、單角、獠牙、虎紋腰布、狼牙棒握在手上、腹部呼吸、大笑、嘟嘴、歡呼 |
| 黑貓 | 約 1,900 | 27 | 四足骨架、多節尾巴、耳朵轉向、頭部追蹤、跳躍、舔毛、伸懶腰 |

三角面數低於計畫的初始預算（主角 15k–35k）：在 ASCII 畫面中，一格字元覆蓋好幾個像素，再多的面數也看不出差別；預算優先花在**關節輪廓**（手肘、膝蓋、手指在近景與 3D 模式中可辨識）。

**動畫**：`CharacterAnimator` 建立在 three 的 `AnimationMixer` 上，動畫片段是以姿勢函式取樣產生的標準 `AnimationClip`：

- 移動層：Idle／Walk／Run 依速度混合；步伐相位依「實際走過的距離 ÷ 步幅」推進，**速度怎麼變都不打滑**；開始走、停下、原地轉身（TurnLeft／TurnRight）自動疊上過渡。
- 動作層：Crouch、Pickup、Inspect、Reach、Grab、Release、OpenDoor、CloseDoor、UseKey、CrankWell、LightLantern、OfferItem、Talk、Startled、Cheer，以 crossfade 蓋過移動層。
- 動畫事件：在接觸的那一格觸發（撿起道具、門環被握住、鑰匙轉動、門扇開始轉、火點著）。規則狀態先提交（存檔一致），畫面在事件時才變化；非關鍵動作可被移動取消，取消時尚未觸發的事件立刻補發，規則與畫面不會不同步。
- 移動與轉身：速度有約 0.1～0.3 秒的加減速；轉身用臨界阻尼彈簧，角速度從 0 平順加速再減速。
- 後處理：腳踩地形的雙骨 IK（骨盆高度平滑跟上）、手部 IK（轉轆轤時手跟著曲柄、點燈時手把燈籠送進火室，權重依動作時間淡入淡出）、看向目標、眨眼與說話嘴型、彈簧骨（辮子、댕기、衣帶、裙擺）受慣性與風場影響；彈簧骨用時間修正的 Verlet，每格的時間平均切成小步、錨點在小步之間插值，60／120／144 Hz 或掉格時擺動都一致。
- 所有隨時間變化的平滑都依實際經過的時間換算，不用「每格乘一個係數」，畫面在不同幀率下表現一致（`npm run test:stability` 驗證）。
- 燈籠：掛在右手腕的單擺，跟著手的加速度與風擺動、有阻尼與角度限制，不穿進身體。

## 9. 環境動態規範

- **風場**（`Wind.js`）：全村共用，主風向緩慢旋轉＋陣風。火焰、炊煙、草、樹、布條、落葉、辮子、衣帶、燈籠都從這裡取風，所以一陣風吹過時所有東西一起反應。
- **火焰**（`Fire.js`）：兩片交叉面＋噪聲扭曲的淚滴形，白黃核心、橘色外焰、紅色邊緣，會伸縮、隨風傾斜；點燈時從小火苗慢慢長大。ASCII 模式中是一塊有尖端、會傾斜的亮區，Hybrid 模式保留柔和光暈。
- **門**（`DoorController.js`）：Locked → Unlocking → Closed ⇄ Opening ⇄ Open ⇄ Closing，被擋住時 Blocked 並自動退回打開。角度用 dt 推進，與幀率無關；狀態改變時同步更新碰撞與尋路網格；存檔恢復時角度直接套用。
- **水井**：轆轤以明確的起始與目標角度轉動（不依幀數累加），繩子收短、水桶上升、離開水面時有水花與滴水。
- **池塘**：水波、玩家靠近時的漣漪、月亮回歸後出現月亮倒影。
- **植被**：草葉在頂點著色器中隨風彎曲、被玩家推開；樹與布條低頻擺動；落葉飄落。

## 10. 鏡頭語言

| 模式 | 用途 | 規則 |
| --- | --- | --- |
| 遠景（探索） | 看路、地標 | 高角度；預設 |
| 近景 | 看角色的關節、手部與衣物 | 同一個方位角、低角度；主角約占畫面高度 35%～40%（單元測試驗證 25%～45%）。V 鍵或右上角按鈕切換 |
| 調查 | 石燈刻紋、屏風、腳印、符咒 | 從主角肩後看著物件 |
| 對話 | 장승、할머니、黑貓 | 從兩人連線的側面，同時拍到兩個角色，選靠近原鏡頭的那一側，不會突然跳到背面 |
| 操作 | 開門、轉轆轤、倉庫 | 低角度近景拍主角與機關 |
| 過場 | 開場、금줄斷開、도깨비登場、月亮回歸 | 固定構圖，平滑推移 |

所有切換都是平滑過渡；遠景與近景的操作方向相同；可關閉鏡頭震動、可減少動態效果。
