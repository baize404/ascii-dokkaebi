# Dokkaebi: Beyond the Moon 4.0：垂直切片「斷橋與燈」遊戲設計文件

> 範圍：只寫這個垂直切片（`prototype.html`）用得到的設計。正式版遊戲（`index.html`）在 4.0 只移除了 ASCII，其他系統還沒換成這一套（Phase 10）。
> 驗證標記：**自動化**＝本機 Playwright／Vitest 跑過；**原始碼**＝讀程式確認；**推測**＝設計推論，還沒驗證；**未驗證**＝需要真人或實機。

## 1. 定位與代表作的一刻

- **定位**：韓國民俗奇幻 × 第三人稱 3D 冒險 × 環境解謎 × 雙重世界（人間／月亮的另一面）。
- **代表作的一刻**（目標，推測）：玩家站在斷橋頭，舉起燈籠開靈視，看著青色的記憶一片一片拼回橋板；接著聽見風聲變大、看見火盆的煙往西倒——他知道現在不能走。
- **玩家要記住的事**：「燈火、風、記憶」三件事彼此牽動，而且他是靠觀察想出來的，不是被告知的。

## 2. 規則（rules.js，純邏輯，單元測試覆蓋）

| 規則 | 內容 | 驗證 |
| --- | --- | --- |
| R1 燈火 | 火力 0–1；峽谷風超過門檻 0.3 才消耗（×1.9／秒），否則每秒恢復 0.8；歸零熄滅，要到火盆重點 | 自動化 |
| R2 舉燈 | 照得更遠（光距 8→13 公尺）、能讓石碑刻紋顯影；舉著時風的消耗 ×1.8 | 自動化 |
| R3 靈視 | 燈亮著才能開；記憶物件依 `MemoryState` 成形，燈一熄靈視就結束 | 自動化 |
| R4 風 | 7 秒一輪（平靜 3.8／預兆 0.8／陣風 2.4）；**閘門開啟程度連續影響風力**：風 = 陣風 × (0.15 + 0.85 × 開啟程度)；全關時燈不會被吹熄、半開時仍然危險 | 自動化 |
| R5 記憶的殘影 | 人間也看得到斷口上沿著橋板形狀飄的青色光塵（3.x 是 ASCII 線條，4.0 改成純 3D） | 原始碼；新手看不看得懂：未驗證 |

### 記憶物件狀態（畫面、碰撞、導航一致）

`hidden → revealing（0.6 秒，不能走）→ stable ⇄ unstable（火力 < 0.45：閃爍、抖動，仍可走）→ dissolving（0.45 秒，還撐得住、角色驚嚇）→ hidden（掉落）`

- 成形到一半就關掉：直接回 hidden，不會留下踩得上去的半座橋。（自動化）
- 碰撞與導航在每次狀態改變時重建；正在走的路徑如果被切斷會重新規劃或停下並說明。（原始碼）

### 擋風閘門機構（`GateMechanism`）

- 手柄實際轉的角度決定擋板高度：約 2.7 圈從全開到全關（捲筒半徑 0.19 m、齒輪比 2.3、行程 7.4 m）。
- 狀態：`open / closing / closed / opening / partial / blocked`。轉到一半停手會停在半途（有棘爪）。`blocked`：關的路徑上有東西時停住——**這一關沒有能擋住擋板的物件**，只有單元測試覆蓋。

## 3. 謎題流程與合法解法

```
起點 → 石碑「眼」（調查、舉燈顯影）→ 學到靈視
     → 溝上的記憶木板（第一次安全地用靈視走路）→ 石碑「風」（暗示閘門）
     → 斷橋：A 看時機過橋（煙／草／布條／HUD 風勢）　B 轉絞盤降下擋板　C 擋板降一半＋看時機
     → 對岸 → 點亮山寺小殿前的石燈 → 結局
```

| 情境 | 結果 | 驗證 |
| --- | --- | --- |
| 沒調查石碑就開靈視 | 可以（Q 隨時可按）；第一次開會記入日誌 | 原始碼 |
| 先找到絞盤、先關閘門再探索 | 可以，閘門狀態保留 | 自動化（keyboard 情境的順序之外由 camera 情境覆蓋半關） |
| 不關閘門看時機過橋 | 隨機出發成功率約 39%（模擬）；看準風停出發穩定成功 | 自動化 |
| 在橋上舉燈 | 消耗 ×1.8，更容易熄 | 自動化（單元） |
| 在橋上主動關靈視 | 崩散 → 掉落，原因「自己收起靈視」，燈還亮著 | 自動化 |
| 火力耗盡 | 崩散 → 掉落，原因「風」，燈熄，提示回火盆 | 自動化 |
| 重複掉落 | 第 2 次給「看煙」提示、第 4 次給「閘門」提示 | 自動化（單元） |
| 中途開說明／日誌／暫停 | 世界、風、遊玩時間都停 | 自動化 |
| 中途切換鏡頭 | 不影響規則；移動基準平順跟上 | 自動化 |
| 互動期間重新整理 | 這個切片沒有存檔：重新整理回到起點（不會卡住） | 原始碼 |
| 不同畫質、裝置速度 | 規則與畫質無關；dt 上限 0.1 秒避免跳格 | 原始碼；實機未驗證 |

永久卡關：所有掉落都回到安全點、火盆永遠可以點燈、閘門可以來回轉，沒有找到不可逆的失敗狀態。（原始碼＋自動化）

## 4. 互動（InteractionController）

`idle → approach（尋路到站位）→ align（轉身）→ engage（動作＋鏡頭）→ contact（手碰到）→ commit（依實際進度生效，只一次）→ recover → complete`；例外 `cancel / failed / interrupted`。

| 物件 | contact 的依據 | commit 的進度 | 可取消 |
| --- | --- | --- | --- |
| 火盆（點燈） | 動畫事件 `ignite` | 立即；燈籠火力從 0.12 依規則自然長回來（火焰形成） | 接觸前 |
| 火盆（觀察） | 動畫事件 `look` | 立即，說明目前的煙 | 接觸前 |
| 絞盤 | 左手 IK 移到握把（0.35 秒） | 擋板實際位置（GateMechanism） | **轉動中也可以**（停在半途） |
| 石碑 | 進入調查視角 | 玩家離開調查 | 隨時（E／Esc／按鈕） |
| 石燈 | 動畫事件 `ignite` | 立即；石燈火焰慢慢長大 | 接觸前 |

石碑調查：按住 F 舉燈、WASD／搖桿移動燈光；燈光照過刻紋的地方才浮現，照過六成筆畫就整個浮現並記入日誌。燈沒舉起來時會說明「光不夠亮」。（自動化：真實鍵盤掃描成功）

## 7. 時間

`real`（真實）／`presentation`（畫面動畫，暫停時停）／`world.time`（世界與風的時鐘，暫停時停）／`play`（只在 playing、inspect、falling 累積）。開場、結局、暫停不算遊玩時間。（自動化）
